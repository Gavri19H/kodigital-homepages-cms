Section 0

How this contract guarantees zero deviation

One approved design + this enumerated spec + an automated fidelity harness = a build that cannot silently drift. Every visible pixel, every string, and every stored value has exactly one defined source, and CI blocks any merge that diverges.

There is no fourth source. If a builder needs a value not found in A or B, that is a contract gap — it is raised and resolved by amending B, never invented in code.

0.2 Definition of done

  • Every row of the Appendix C traceability matrix has a passing automated test.
  • The four fidelity gates in §13 are green in CI: visual-regression, string, geometry, behavior/storage.
  • No control writes any field not named in §11. No screen renders any string not listed in Appendix A (for the fixed-fixture Section "Zip / Insurance / Car").
  • Zero new runtime, payload, analytics, auction, or activation behavior beyond what §1.3 amends.
Interpretation rule. Wherever this contract says “exact”, it means literally: the harness asserts the value. Wherever it says “operator words” or lists copy in “quotes”, that string is asserted verbatim. Wherever a pixel or token appears in a table, it is a constant, not a suggestion.
Fidelity vs function (v3.1 rule). The golden master fakes some logic — its undo, drag-measurement and theme editing are visual stand-ins. Binding split: affordances & pixels are design-locked (Artifact D — copy the chrome verbatim); logic is contract-locked (§6–§10 define the real behavior behind each affordance). Where the DC hardcodes a demo value (e.g. “≈ 384 px”), the contract's formula wins and the real UI renders the true measured value in the identical format. Anything labelled PROPOSED is not in the approved design: implement storage/behavior as specified but add no visible UI for it without a design addendum.

Section 7 · Concern 1 — resolved

Sizing model: presets vs manual custom

Presets are the funnel's shared size language; a manual drag is an explicit, deliberate one-off that overrides the preset for that one field. This is the accepted resolution of the preset-vs-manual conflict.

7.1 The rule (normative state machine)

  1. A field's Width and Height each resolve in priority order: node override → funnel theme default → design default. With no override, the field inherits the theme's Field height / width defaults (§10.4).
  2. The Style tab exposes Width as segmented [S · M · L · Full] and Height as [Small · Medium · Large]. Selecting a preset writes that preset name to the node and clears any custom value.
  3. Dragging a side handle on the canvas sets the width to a numeric Custom value and overrides the preset. On entering Custom: all preset segments deselect; a highlighted “Custom · ≈ N px” chip appears in the Style tab with a Reset control; a live “≈ N px · custom” badge appears at the field's top-right on the canvas; the field renders at the custom width. Measurement formula (binding): stored value = the drag's measured content-box width in px, snapped to a 4px grid, clamped to [200, 600]; the badge and chip render “≈ {value} px”. The golden master hardcodes the demo value 384 (= 64% of the 600 column) because it fakes the drag — the real UI measures and shows the true value in the identical format (§0 fidelity-vs-function rule).
  4. Reset removes the custom value → the field re-inherits the theme preset (demo resets to Full). Reset is the only way back to the shared language; presets and custom are mutually exclusive per axis.

7.2 Storage (binding)

// component node in leadgen_sections.content_json → node.design_overrides { "size": { "width": "full" | "s" | "m" | "l" | { "custom_px": 384 }, "height": "medium" | "small" | "large" | { "custom_px": 56 } } } // absent key = inherit theme default (the shared language) // string = named preset (still inherits the preset's resolved px from the theme) // {custom_px} = manual override; wins over preset AND theme; Reset deletes the key

Custom px is clamped to the unit column and snapped to a 4px grid. No raw CSS is ever written; the renderer maps preset names to the theme's resolved sizes and custom_px to an explicit width, so runtime and both preview paths stay byte-identical (§12).

7.3 Copy (asserted)

  • Style note: “Presets keep every question in the funnel consistent. Drag a handle on the canvas for a one-off size — it becomes Custom and overrides the preset here.”
  • Custom chip: “Custom · ≈ 384 px” + sub “Set by dragging on the canvas — overrides the preset” + “Reset”.
  • Style header right meta: “from theme: Navy”.
Open decision carried into build. v3.0 ships width as the manually-resizable axis (side handles); height is preset-only unless the product owner opts height into custom (top/bottom handles) — the storage shape above already supports it, so enabling height is a UI-only change, no schema impact.

10.1 Model (additive — no new table)
