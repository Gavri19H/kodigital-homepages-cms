- Worker package lives under `api/` (separate from repo root); `api/package.json` carries all worker scripts (dev/test/typecheck/verify/db:migrate/deploy).
- Use `tsx` to run TypeScript scripts (e.g., verify scripts) without a build step.
- `compatibility_date` for wrangler is mission-pinned ("2026-05-06") — do not bump silently.
- Banned legacy production identifiers (must NOT appear in active code/config): `theiwise.com`, `a2z-cf-cms-v1-api`, `a2z-cf-cms-v1-db`, `insureprimo`, `quotesRoutes`, `psychic-quiz`, `rental-booking`. - Verify script must self-exclude and exclude legacy reference docs (docs/source-architecture.md, docs/no-touch-red-line.md, docs/reference/current-theiwise-technical-spec.md).

- **Learnings for future iterations:**
  - The Phase 1.5 routing contract is split across THREE keys: ADMIN_HOST (hostname only, no scheme), ADMIN_BASE_URL (full URL incl. scheme), ADMIN_BASE_PATH (path prefix). Future stories must read each from env, not reconstruct from the others — wrangler.toml is the source of truth.
  - When an AC writes `grep '.io'` it is almost always intended as a literal-dot check; the `.` is BRE-wildcard which catches `production`/`version`/`sion` words and makes the AC unsatisfiable in a real wrangler.toml. Treat the parenthetical ("no .io domain references") as the binding intent.
  - Wrangler does not merge [vars] from top-level into [env.<name>.vars]; each env block must repeat every key. Forgot to also re-declare ADMIN_HOST in env blocks would leave staging/production with only top-level "localhost" — staging/production deploys would silently behave like local dev.
